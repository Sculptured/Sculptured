# Changelog

All notable changes to Sculptured are listed here. The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and versions follow [Semantic Versioning](https://semver.org/).

## [Unreleased]

### Fixed
- Adding a group with a workflow to a project (from Community or your saved groups) now maps every reference to its new agent and stage ids: a stage's reviewers, its escalation agent and round-limit route, stages run by a person or a check (no agent), and the group's schedules, which were dropped. Coding hospital added to a project no longer shows broken Treatment and Code review stages.
- Community item pages on the hosted service no longer fail with error 500.

### Added
- **Proposed changes with rule checks.** A new agent tool, `propose_change`, records a change an agent would make to a business system (`ChangeProposed`, agent-reported). Sculptured evaluates the team's mandate rules on it (`ChangeChecked`, verified: at most, at least, one of, filled in, on dotted fields), approves it when every applicable rule passes and the team allows that, or raises an `approval` question; nobody answering in time means not approved (`ChangeDecided`, `DecisionSource::RejectedOnTimeout`). Settings → Changes to business systems edits the rules; Results → Changes lists every change; Needs you shows Approve and Reject with the change's fields and rule results. See `docs-site/guides/changes.mdx`.
- **OpenCode agents for open models.** A new agent kind, `opencode`, runs OpenCode over the Agent Client Protocol (`opencode acp`): models such as Kimi, GLM, DeepSeek and GPT OSS through OpenRouter. Hosted OpenRouter connections (back in **Setup → Models**, now for open models) run OpenCode agents with `OPENROUTER_API_KEY`. Team tools, integrations, sandboxed-access questions, interrupt and resume work as for Claude and Codex; cost per turn is OpenCode's own estimate. Driver tests replay recordings of OpenCode 1.19.4 (`crates/fixtures/recordings/opencode-*`). See `docs-site/guides/open-models.mdx`.
- Status page: one Markdown page per team, under Results → Status, that says where the work stands and what changed, so you can come back later and read it instead of the transcripts. One agent writes it with the new `write_status` tool: the agent chosen under Advanced → **Status page**, else the workflow's collector, else the agent at the end of the line. Its briefing tells it to keep the page current while it works and to write a final version (`done: true`) when the work is finished. Every version is kept and readable from **Version**; the page refreshes while open and stays after the team stops. Agent-reported. Docs: [The status page](docs-site/guides/status-page.mdx).
- Model connections, server side: `DraftAgent.connection` (a connection id the gateway keeps; Claude agents only) reaches the compiled seat (`MemberSpec.connection`, `CompiledSeat.connection`). Team files, MADL and portable exports never carry it. On the hosted service a Claude agent with a connection gets its settings at launch from the gateway (`POST /internal/connection-env`, signed like analytics, `controld::gateway`) into `LaunchParams.env` only; they are never stored, recorded, logged or put in an error. A connection that can't be read keeps the agent from starting with "Couldn't read the model connection for <agent>: <reason>. Check it under Setup → Models." Local mode ignores connections. The runner takes only `host_proto::MODEL_ENV_KEYS` (Anthropic key, auth token, model, and OpenRouter as the only base URL) from the server (runner feature `model-env`; an older runner is refused rather than run on the computer's own sign-in).
- Setup progress: `GET/PUT /api/setup` (`SetupProgress { done, skipped }` of `SetupStep`: `welcome`, `computer`, `models`, `computers`, `tour`; deduplicated, a done step is not also skipped, an unknown step is `setup_step_invalid`), kept in the settings key `setup`. Docs: [Set up your account](docs-site/guides/setup.mdx).
- Projects: tick projects (or all of them) to hide them or move them to the Trash together; in the Trash, tick projects to restore them or delete them forever after one confirmation. Running projects can't be moved to the Trash.

### Changed
- Setup → Models no longer offers Claude via OpenRouter, which isn't finished. Connections added before still list and run; the server side is unchanged.
- Autosave no longer shows "saving…" on screen: on an agent's setup page it popped in above the fields while you typed and pushed the page down and back. Saving is still announced to screen readers, and a failed save still shows with Retry or Reload.
- Practice agents are gone from the UI. Every agent is a Claude Code or Codex agent: the team generator no longer offers a Practice option (and its AI can no longer choose `practice`), Setup's first project is a Builder → Reviewer team of two Claude agents instead of a free practice team, and the tour and help text no longer mention them. In Logos style a Practice agent left in an older team now shows the robot mark instead of a flask with rising bubbles. `AgentKind::Practice` and the stub driver stay, hidden, for the test suites.
- A workflow without a project folder shows one issue, `project-folder-needed` ("Choose the project folder: … run there."), instead of one per user (copy per item, guard, dispatch command, each check stage). **Things to fix** offers **Choose folder…** for it, and on the hosted service a **Run on** choice for a team without a computer.
- A team whose settings were never saved runs on the computer chosen last under **Run on** (`last_team_host`); choosing Automatic for a team keeps it automatic.
- Hosted teams across computers: an agent on its own computer (`TeamSettings.agent_hosts`) without a folder of its own starts in `.`, which its runner resolves to that computer's first allowed folder, instead of the project folder (a path on the team's computer). A team whose agents all have their own computers needs no team computer. On the hosted service `folder-missing` is not an issue. The agent's **Computer** sits above its folder, and its folder picker browses that computer.
- Add a cluster: the sign-in choices are cards with a visible selection. A site that offers a password but no key sign-in is refused with "does not take keys", and the card drops the authorized_keys steps.
- Fewer tokens for teams (measured on a Codex lead with two workers, 4 runs before and 5 after, all 12 tests passing each time: mean 795k → 639k tokens, tokens in turns with no tool call 148k → 32k, turns 7–9 → 4–5):
  - A `send_agent_message` marked `fyi` to an idle agent is held (`held_notes`, migration 29) and prepended to its next message or workflow assignment instead of starting a turn.
  - A message an agent sends the agent it hands work to during its work turn is recorded as that handoff (`HandedOver` on the agent's own message, `Store::record_adopted`); the result is not sent again, and the receiver's turn on the message is its work.
  - `team_status` is one line per agent; `complete_work` answers in one line instead of the whole batch.
  - Briefings carry a connected teammate's job up to 1,500 characters and a group member's job as its first line; an agent's own job stays whole. They say AGENTS.md and CLAUDE.md are already loaded and ask for no acknowledgements.
  - Codex agents get `model_auto_compact_token_limit` at twice the team's context ceiling (`LaunchParams.compact_tokens`), so a long turn compacts before it reaches the model's window.
  - The protection guard refuses a shell step that sleeps longer than 30 seconds and says to end the turn instead.

### Added
- Cluster sign-in (`web/src/hosted/ClusterAdd.tsx`, `ClusterQuestion.tsx`, `ClusterCertificate.tsx`): OpenSSH user certificates (`auth: certificate`, `POST /gw/api/clusters/{id}/certificate`), held signed-in connections (`hold_hours`, `held_until`, `POST …/sign-out`, `…/settings`), every prompt of a keyboard-interactive round with its name, instructions and links, a push hint and a countdown (`question.expires_at`).
- Clusters on the hosted Computers page (`web/src/hosted/Clusters.tsx`, gateway routes `/gw/api/clusters*`): add a login node (host, port, user, optional jump host; a key the server makes, a pasted key or a password), answer its MFA questions in place, see the authorized_keys line, the doctor report and the audit log of every SSH action; Reconnect and Remove.
- Questions pages: `GET /api/teams/{id}/questions` (every question of a team, newest first, at most 500; the agent list now returns up to 200); the project's **Questions** tab (`/p/:team/questions`) and each agent's **Questions** tab (`questions/QuestionLog`): open questions answered in place (the existing question card), answers with the offered choices and the one picked, the agent's own decision on expiry, late answers, withdrawn ones; filters by outcome and agent.
- Question urgency (agent-reported, an idea from Gas Town's escalation severity): `request_input` takes `urgency` (`low` | `normal` | `high`, `model::Urgency`, `QuestionPrompt.urgency`); the inbox sorts high first and low last, and the question card marks urgent ones. No re-escalation: an unanswered question still times out to the agent's own decision.
- Waves on the item board (an idea from Gas Town's convoys): `itemBoardModel::waves` levels a batch's items by `depends_on` (unknown ones ignored, cycles cut) and the board lists each wave's state and count; shown only when there is more than one wave.
- `sculptured doctor` (an idea from Gas Town's `gt doctor`): the CLIs' install and sign-in (`localops::clis::status`), the built-in components' programs (`hostd::supervisor::find_program`, now public), and each runner's allowed folders, approvals and secret names. Read-only.
- Re-briefing after compaction (an idea from Gas Town's `gt prime`): `LaunchParams.briefing` for protected Claude agents, written by the runner to `briefings/<seat>.md`, given back by a `SessionStart` hook (matcher `compact`) running `sculptured rebrief`.
- A computer's own cap (an idea from Gas Town's scheduler): `host_limits` (`PUT /api/hosts/{id}/limit`, `max_working` in `GET /api/hosts`) holds new messages for any agent on that computer while that many work there across all teams (`gate::busy_on_host`), released by the same slot delivery as the team cap; set on the Computers page.
- Silent agents (an idea from Gas Town's patrol): a running agent in a turn with no event for 30 minutes (`collaboration::silence::QUIET_MS`), and not waiting in `request_input` or `approve`, gets a heuristic `stall-suspected` event; it sets `SeatView.stalled` with `silent: true`, its next output clears it, and Nudge asks it to say where it is.
- More component kinds: `mcp-remote` (`url`, `headers` whose values name secrets as `${NAME}`; the runner fills them from its environment or `component-secrets.json`, written by `sculptured set-secret`, and passes them to Claude in a private `--mcp-config` file and to Codex through `env_http_headers` variables, never on a command line), `skills` (expanded by the server into the agent's skills via `TeamDraft::agent_skills`, never sent to the runner) and `claude-plugin` (`plugin: name@marketplace`, found through Claude Code's `installed_plugins.json` and loaded with `--plugin-dir`). `program` and `install` are optional where a kind does not need them; existing manifests serialize, and so digest, as before. Runner feature `component-kinds`; an older runner gets the agent without its remote servers and plugins, with a note. The app's per-agent picker groups components by kind, offers Claude-only ones to Claude agents only, and the team's Components has a New component form.
- Components (`model::Component` manifests: `mcp` or `tool-hook`, a bare program name and arguments, briefing, install steps, `requires`, `claude_only`): Kindex and Signet-Eval ship as built-in examples (`crates/model/src/components/*.json`); teams carry their own (`TeamDraft.components`); `AgentAdvanced.integrations` is now a list of component ids. Sent as `LaunchParams.components` (runner feature `components`; built-in ones still by name for older runners). The runner resolves any manifest generically; on a connected computer a manifest that is not built in runs only once its digest is in `approved-components.json` (`sculptured approve-component <digest>`, read at each launch). Briefing lines come from manifests. Community stores component blocks (`{"kind":"component","component":…}`), lists their `kind`, and publishes the built-in ones as official examples; the app shows them with their command and adds them to a team. Agent cards show component chips; the team's Advanced settings list, add and share components.
- A refused start pops up as a dialog, and a plan hold offers Start anyway, on the Design and Run pages.
- Copy-on-write copies: on a filesystem that clones files (APFS, btrfs, XFS, ReFS), an agent's or item's own copy is cloned from the project (`localops::clone`, `reflink-copy`) and brought to its branch by git, so it shares the project's disk and keeps its ignored build output; elsewhere it is an ordinary worktree checkout as before.
- Safety rules (`TeamDraft.safety`, `model::SafetyRule`, Signet-Eval's rule format): checked first by `sculptured guard` for every Claude agent with protections on, with presets (`web/src/structure/safety-presets.json`, shared with the Rust side) and `safety-rule-invalid` draft checks; a rule that cannot be read never matches. Integration `signet`: the runner finds `signet-eval`, writes the team's rules as its `--rules-path`, and adds it as a second PreToolUse hook (`LaunchSpec.tool_hooks`); it brings `kindex`, whose engagement its locked rules require.
- Review panels: `WorkflowStage.personas` gives each reviewer an angle (`ReviewPersona`), told in its assignment; a split vote starts the panel's result with who voted what (`engine::split_note`). Ideas from Advocate.
- Shared values in contracts (`DataAccess.shared`, `name = value @ file`): checked in their files by the project-map op at every start (`ProjectMap.shared`, found with line / missing / no-file), told to agents, shown in Knowledge. An idea from Constrain's boundary register.
- Claim checks (`claims.rs`): at each completed turn, a claimed file change without a captured edit, or "tests pass" with no command run, is logged as a heuristic `claim-check` entry. An idea from Arbiter.

### Fixed
- `sculptured run` with a long `--data-dir` failed to bind the agent tool socket (path longer than a Unix socket allows); the socket now goes in a private folder under the runtime directory when the path would be too long.
- Contract write limits were never enforced: the guard hook matched only `Read|Bash`. The matcher now includes the edit tools when a contract limits writes, and every tool when safety rules exist (`GuardRules::hook_matcher`).
- Agent skills (MADL MEP 0004): `AgentAdvanced.skills` (`model::Skill { name, description, body }`, Agent Skills format, checked as `skill-invalid`), edited on the agent panel (full-size editor, Load from file for a `SKILL.md`). Sent as `LaunchParams.skills` (runner feature `skills`): Claude Code gets a per-agent plugin folder in the runner's data dir via `--plugin-dir`; other CLIs get the list in their briefing and a `read_skill` agent tool. MADL embeds them; named-only skills are reported as not imported.
- Integrations: `AgentAdvanced.integrations` (`kindex`), sent as `LaunchParams.integrations` (runner feature `integrations`). The runner finds `kin-mcp` itself and adds it as an MCP server (Claude `--mcp-config`, Codex `mcp_servers.kindex.*`); missing, the agent starts without it and a `features-dropped` note says how to install it.
- Constraints and lessons kept with the project: `record_lesson { kind: constraint }` (source `constraint`, first in briefings); confirming a lesson or constraint keeps it in each team folder's `.sculptured/lessons.md` (`LocalOp::KeepLesson`), and `ProjectMap.kept` brings those lines into later teams' briefings.
- Knowledge: a project map of each agent folder made on the agents' computer at every start (`LocalOp::ProjectMap`, written to `.sculptured/map.md`; areas, file kinds, notes, Markdown sections with line ranges), kept per team (`project_maps`), with its outline and who worked where in each agent's briefing; agent tools `search_history` (the team's history, no model call) and `record_lesson` (into the decision log as `source: lesson`, told to every agent at its next conversation; `confirmed_ms`, `POST /api/teams/{id}/decisions/{entry}/confirm`); `GET /api/teams/{id}/knowledge` and the Run board's Knowledge view with a quiet count of new lessons.
- Agent contracts (MADL MEP 0003, from Pact): `AgentAdvanced.data_access` (reads, writes, side effects, rationale) and `authority` (domains, `scope`: a group or the whole team). The briefing tells every agent who decides what, how far each owner's decisions reach, and its own contract; protections refuse Claude agents' `Read`/`Write`/`Edit`/`MultiEdit`/`NotebookEdit` calls outside it (`GuardRules.reads`/`writes`, resolved against the agent's working folder). Edited under the agent's Advanced → Contract. The design assistant and team generator follow research-based design rules (split along real dependencies, one owner for cross-group decisions, tests over approval, few connections).
- Protections (team Advanced, on by default): a Claude Code `PreToolUse` hook (`sculptured guard`, passed with `--settings`) refuses whole reads of files over 100 KB (images, PDFs and notebooks excepted) and whole-file shell printers; shell output is capped at 8,000 characters (`bashOutputMaxChars`, with `--autocompact 100000` as a backstop); and an agent whose context passes 60,000 tokens writes its notes between turns and continues in a fresh conversation (Claude and Codex). New `TeamDraft.protection`, `LaunchParams.protection` (runner feature `protection`), events `protection-applied` and `context-ceiling-reached`, and per-call `context-reported` from the Claude and Codex parsers.
- Upload in the Input: the folder picker can choose files (`GET /api/folders?files=true`, `LocalOp::ListFolder.files`, `FolderListing.files`; names and paths only, no dot-files), and their full paths are added to the Input for the agents to open. An older runner lists folders only, and the picker says so.
- The team's model setting lists the agents whose own or group model wins over it, with "Use the team models for every agent".

### Fixed
- A runner whose account disconnected its computer exited with an error every time, and its login service started it again every 5 seconds, all day. It now exits with code 78, which the systemd service does not restart (`RestartPreventExitStatus=78`), and turns its own login service off (systemd, launchd or Task Scheduler). Connecting again turns it back on.
- The Run board polled every message ever sent to the team (`/communications`; 47 MB every 5 s for a 26-agent team whose handoffs carry the briefing). It now asks for the latest run's events with long text cut (`?run=latest&brief=true`): 49 KB, and on that team no more 200 ms freezes and 10 MB instead of 177 MB of page memory.
- The live graph draws only cards, groups and arrows near the screen (off-screen agents keep a focusable stand-in); long agent lists skip off-screen rows; the browser's live event list keeps long tool output and briefings cut, and the open agent loads its events in full.
- Plan budget meters say they count the run's own share of the window ("this run used 26% of the window · it may use 30%").
- An agent whose message waits for a free slot ("most agents working at once") was shown as stuck ("the handoff … was not delivered"), and agents after it as "waiting on … (stuck)". A held handoff now counts as on its way; `SeatView.slot_wait` and a `message-held` event say the agent waits for a slot, and the board shows "waiting for a slot to run".

### Changed
- Faster pages while a team runs: `GET /api/teams/{id}/communications` returns only message, handoff, start and capture-gap events (`?usage=true` adds model-usage reports), not tool calls; one `GET /api/teams/{id}/recent?tail=` replaces a request per agent; the Run board recomputes its arrows only when a message or handoff arrives; per-message sizes and downstream sets are cached. Smaller logo files and cache headers for built assets (`/assets/` immutable, `/brand/` one day).
- Wording: Sculptured is for teams of agents, not only coding agents. The Design board's arrow key sits on the board's corner; the team folder button says "Choose folder" when none is set.

### Added
- One computer, several accounts: a connect key for an account other than the computer's runner's gets a runner of its own in `~/.sculptured/runners/<id>` with its own service name (gateway `POST /gw/api/device/same-account`); `sculptured stop` covers every account's runner.
- `sculptured stop` ends every agent this computer's runner started, without the server (process groups recorded at launch, checked by start time). Stopping agents whose computer is offline marks them stopped at once; a reconnecting computer ends any agent the server has stopped.
- Delete a trashed project forever (`DELETE /api/project-visibility/{id}`): its design, runs, history and reports; not its folder or agents' copies.
- Plan budgets can pause a run at their hard value and continue it after the window resets (`PlanBudget.pause`: `continue_with` notes or resume, `max_windows`), with a checkpoint wrap-up, `BudgetState::Paused`, `POST /api/teams/{id}/budget/paused` (continue, stop, mode), `budget-state-changed` states `paused` and `continued`, and the MADL extension `plan_pause`.
- The team briefing goes with an agent's first message per conversation only, and covers its group and connected agents in full and the rest by name. The workflow tools are offered only to teams with a workflow (`SeatToolsParams.workflow`, `SCULPTURED_SEAT_WORKFLOW`).
- Where tokens went: a report per run made on the runner by MAIS from the CLIs' session files (`analyze-run`, `usage-reports` capability), kept by controld and refreshed every minute while a run goes (`GET /api/teams/{id}/report`), shown on the Run board and in History. `budget-state-changed` events.
- Import a Claude Code session (with its subagent files) or Codex rollouts as a read-only past run and a runnable team (`POST /api/runs/convert`, then the existing `/api/runs/import`), under Advanced. "Improve this team with AI" (`POST /api/teams/{id}/improve-from-run`) proposes a reusable version as a labelled diff.
- Team limits on spawned agents (`limits.max_agents`, `limits.max_child_levels`), set under Advanced; none by default. The fixed caps of 10 children per agent, 64 agents and 4 levels are removed. The Run board folds many children into "+N more" and deep ones into "+N deeper".
- First public release of the Sculptured core under the Apache License 2.0: the team board, live agent control for Claude Code and Codex, workflows with checks, reviews and merges, team files and run files, connected computers, the desktop app and the docs site.
